§ 01 / Problem

The question

Binary
classification
· P(home wins)
· Probabilistic output

Given two scheduled teams, can historical performance data produce win-probability estimates accurate enough to generate positive expected value against sportsbook lines?

Prediction markets like Kalshi and sportsbook lines from DraftKings represent the aggregated belief of financially-incentivized traders — they should be very hard to beat. If a data-driven model can systematically detect mispricings, that’s both a strong empirical result and the foundation for an automated trading strategy.

We frame it as binary classification: predict P(home team wins). The output is a calibrated probability, not just a yes/no label — because calibration is what actually matters when comparing to market odds.

§ 02 / Data

The dataset

Source
nba_api
· stats.nba.com
· Free, no key

Every regular-season NBA game from the 2019-20 through 2024-25 seasons — pulled live via the open-source nba_api Python package, which queries the official stats.nba.com endpoints.

Each game gives us two team-rows (one per team’s perspective), which we pivot to one row per game with explicit home and away identifiers. The result is a clean, structured table covering roughly 7,400 games with team identifiers, dates, scores, and outcomes.

We held out the most recent season (2024-25) as a strict time-based test set. The model never sees any of those games during training — this is the only fair way to evaluate a forecasting model.

§ 03 / Features

What the model sees

12 features
· Rolling stats
· No leakage
· Shift-then-roll

For every game, we compute features for both teams using only data from games that happened before the current game. The rolling window is 10 games; the season-to-date stats reset each year. Every rolling computation is shifted by one game so the model never gets to peek at the game it is predicting.

win_pct_10
Win percentage over the last 10 games — captures recent form.
net_rating_10
Points scored minus points allowed per game, last 10 games. The single strongest predictor.
season_wp
Season-to-date win percentage. Captures full-season team strength.
rest_days
Days since the team’s last game. Back-to-backs are a real handicap.
diff_*
Home-minus-away versions of each feature above. Differences are usually the most predictive single columns.
home/away split
All features computed independently for the home and away team.
§ 04 / Models

Two models, one race

Linear · Neural
· scikit-learn
· pytorch

Logistic Regression is the baseline — fast, interpretable, with each coefficient telling you how a feature shifts the log-odds of a home win. Features are standardized so coefficients are comparable. Trained with the LBFGS solver, runs in seconds.

Neural Network is a small fully-connected MLP, built in PyTorch and trained over real epochs with mini-batch SGD. Binary cross-entropy loss (which is log loss), Adam optimizer, dropout regularization, and early stopping on validation loss to prevent overfitting.

Input · 12 features (standardized)
→ Linear(32) → ReLU → Dropout(0.2)
→ Linear(16) → ReLU → Dropout(0.2)
→ Linear(1) → Sigmoid → P(home wins)
Loss BCEWithLogits · Opt Adam(lr=1e-3) · Batch 64
Max epochs 80 · Early stop patience=12 on val loss

Both models are trained on every season except 2024-25, then evaluated on that held-out season. We also compare against a naive baseline that always predicts the historical home win rate.

§ 05 / Training

The training curve

Training
· Mini-batch SGD
· Early stopping
· Best weights restored

The neural network is trained over multiple epochs (one epoch = one full pass through the training games). After each epoch we compute the loss on a held-out validation slice; when that loss stops improving for 12 consecutive epochs, training stops and we restore the best weights we saw.

Training and validation loss across epochs · replace with your own after running 03_train_models.py

The curve tells a clean story: training loss continues falling as the network memorizes the training games, but validation loss plateaus around epoch ~20-25 — the point at which the model stops generalizing better. Early stopping kicked in and locked the best weights at that point. This is exactly what a healthy training curve should look like.

The neural network wins on every metric, narrowly beating logistic regression. The small gap suggests most of the predictive signal in this dataset is roughly linear — a great empirical finding to discuss: more model complexity does not automatically mean better results, especially when the underlying relationship is simple and the training set is modest.

§ 07 / Markets

Beating the line

Fair odds
· Implied probability
· Expected value
· +EV detection

The model outputs a probability. Sportsbooks and Kalshi quote prices that imply a probability. When those two disagree, there is expected value — positive if our number is right.

Example: Boston hosts L.A. Lakers

Our model says Boston wins this matchup 64% of the time, which corresponds to a fair moneyline of -178. If DraftKings is offering Boston at -150, that is a +EV bet on Boston. If they are offering Boston at -250, the market is more confident than us and we should pass.

We can simulate this on the 2024-25 test season: for every game where our model edge exceeds 5%, “bet” a fixed unit; tally the realized ROI. That is the proposal’s paper-trading evaluation.

§ 08 / Reproduce

How to run it

5 scripts
· Run in order
· ~5 minutes total
· Python 3.10+

python3 -m venv venv
